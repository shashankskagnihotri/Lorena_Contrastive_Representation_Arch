# Saved preprocessing and fixed-example diagnostics

These figures are exported from the studies' saved tensors and fitted statistics. No model inference, image preprocessing, normalization fitting, checkpoint changes, or metric recomputation is performed.

- `parent_fixed_train_val_examples/` contains byte-identical copies of the original 160 signed-panel PDFs, PNG previews, 40 tensor NPZ files, and their metadata for MNIST grayscale and all three CIFAR-10 contrast representations. They cover the original fixed clean training and held-out validation panels at 0, 20, 40, 60, and 80% imposed sparsity.
- `normalization/` contains the original fitted mean/std and guard table, copied fit artifacts, and per-channel before/after-normalization distributions. The fitted table summarizes the full clean training partitions. Distribution figures summarize only the predetermined ten-image clean-training panel at 0 and 60% imposed sparsity; they are not full-population distributions.
- `followup_fixed_examples/` contains standalone multipage PDFs for every active representation, including sparse raw pixels, at inference sparsities 0, 10, ..., 90%. The selection uses seed 0, dense-trained checkpoints, clean inputs, and brightness/contrast/fog at CIFAR-10 severity 3; MNIST uses clean inputs and its released fixed-severity brightness/fog cells. MNIST-C does not supply a contrast cell. Every selected PDF contains all ten original fixed class-balanced examples and all native channels. Each PNG previews the first page only.

The follow-up PDFs display frontend tensors and support masks, without model predictions or activations. The exporter compares every displayed tensor, mask, sample identity, fitted mean/std, and fixed display scale between the saved Swin and ViT diagnostics. A `shared_frontend` PDF is emitted only when these arrays are exactly equal. Otherwise separate architecture directories preserve both versions. Dense unmodified raw-reference cases remain in the full source catalog; compact raw 0% explicitly includes natural-zero patch removal and must not be interpreted as dense execution.

Native and normalized contrast retain their original signed values. All display scales are the original fixed clean-training scales, reused for corrupted inputs. Hatching denotes absent patches; it does not change numerical tensor values. Each rendered PDF has a companion CSV of sample/channel identities, display scales, support fractions, and exact source NPZ paths. Its JSON contains source and output hashes. The source NPZ files preserve every actual plotted pixel, coefficient and support value. No tensors are reconstructed from rendered images.

The inherited channel label `mean_rgb_contrast` denotes the single grayscale-contrast channel. For MNIST, the original frontend internally replicates its one-channel image into three identical channels before computing this one grayscale output. No MNIST single-color or color-opponency results are included. Patch support is shared across all native channels: a patch can remain active even when the displayed individual color channel is entirely zero, because another channel contains a nonzero coefficient.

`full_diagnostic_source_catalog.csv` indexes all 612 registered follow-up cases and their complete official-cell diagnostic directories, including other seeds, training families, architectures and corruption severities. Only selected exported tensors are rehashed by this exporter; the source studies retain their full evaluation evidence. `rendered_panel_catalog.csv` and `.json` identify the exported subset. `selection_policy.json` records the deterministic selection and deduplication rule.

New figures use matplotlib/seaborn with the requested `talk`, `whitegrid`, serif theme, PDF/PNG export at 300 dpi, and companion plot-data CSVs. Normalization figures also have SVG exports. Parent previews retain their original exact files. Figures and pixels are visual diagnostics, not latency measurements or new accuracy results.

`progress.json` records export progress; `completed.json` is written only after every selected panel succeeds. `provenance/launch.json` identifies the allocated CPU job, pinned Python environment and immutable exporter. `provenance.json` records the source-study manifest and original renderer hashes. The reproducible exporter is also maintained at `debugging/render_diagnostic_pdfs_20261008.py` in the project root.
