## 1. The method: follow this exactly

The contrast-model pipeline is:

raw image -> fixed contrast representation -> coefficient sparsification in native contrast units -> identify empty patches BEFORE normalization -> gather retained CONTRAST patches -> per-channel mean/std normalization using frozen 0%-sparsity training statistics -> patch embedding -> compact transformer execution -> supervised classification.

Before any contrast-model training, first stream the entire permitted clean training partition through each of the three frontends at 0% thresholding, calculate that representation's per-channel population mean and standard deviation, validate the results, and freeze them. Do not substitute RMS-only scaling for mean/std standardization.

The model must consume standardized signed contrast values, not magnitudes or clipped positive-only values. Ordinary mean subtraction may change a coefficient's numerical sign; do not discard the original contrast polarity before that standardization. Contrast is not a side channel for selecting original RGB embeddings. Do not concatenate RGB with contrast, reconstruct RGB, introduce an RGB residual branch, use a pretrained RGB backbone, or train on RGB and switch to contrast only at inference.

Train separately at each requested coefficient-sparsity setting:

    sparsity_percent = [0, 20, 40, 60, 80]
    training_seeds = [0, 1, 2]

There is NO independent token-drop budget, keep ratio, q parameter, top-K patch selector, coverage quota, learned router, or minimum-image-token quota. The number of retained patches follows from which patches still contain information after coefficient thresholding. Use the same representation, sparsity setting, and support rule during training and evaluation.

Here, "contrast representation" means the fixed image transform, not contrastive learning. Use ordinary supervised cross-entropy, not a contrastive objective.

### 3.2 Compute each contrast representation's own mean and standard deviation FIRST

Implement a tested `compute_normalization_stats.py` entry point. For every dataset and each of the three VERIFIED contrast representations, visit EVERY image in the permitted clean training partition exactly once in a deterministic, unaugmented pass. For the primary held-out-validation protocol in section 5, this means all 55,000 MNIST training images or all 45,000 CIFAR-10 training images, not the 5,000 held-out validation images. For an explicitly enabled full-training-set refit, make a separate stats artifact using all 60,000 or 50,000 clean training images, respectively.

Use the exact source-matched frontend at 0% coefficient thresholding. Disable random augmentations, coefficient thresholding, token dropping, model-input normalization, and learned layers while estimating statistics. Natural zeros in the frontend output remain valid observations and MUST be included. Compute statistics on native output channels/pixels before artificial model padding or post-frontend channel copies. This is one dataset-wide mean/std VECTOR per representation, not per-image, per-batch, per-patch, per-seed, or per-architecture normalization.

For each native output channel c, over K actual image pixels:

    mu[c] = sum(C0[n,c,h,w]) / K
    variance[c] = sum((C0[n,c,h,w] - mu[c])**2) / K
    sigma[c] = sqrt(variance[c])

Use population variance (ddof/correction=0), not an average of batch or image standard deviations. Run the frontend in its verified float32 arithmetic, then accumulate moments in float64 using deterministic chunked Welford/Chan aggregation or a stable two-pass implementation. Test against a direct float64 computation on a manageable subset, including batches of unequal size. Keep the reduction order fixed and record it. Fail on NaNs, infinities, missing samples, or materially negative computed variance. Do not silently drop awkward images.

This requires transforming all training images, not storing all transformed images simultaneously. Stream the data, optionally evaluating all three modes in one pass through the image loader. Avoid unnecessary large caches. Record the actual number of images and per-channel pixels visited. Never estimate normalization from validation/test images, MNIST-C, CIFAR-10-C, or augmented/corrupted images. It is permissible to log their distribution moments after evaluation as DIAGNOSTICS; they must never update the normalization used by a model.

For constant or numerically degenerate channels, set a fixed guard `normalization_min_std=1e-6` in native frontend units. Save the measured sigma and use `sigma_effective[c]=1.0` when sigma[c] is below this guard; otherwise use the measured sigma[c]. Log every guarded channel and do not amplify numerical noise by dividing by a nearly zero standard deviation. Preserve channel count and do not silently delete opponent channels. Do not alter the frontend or token epsilon to conceal such degeneracy.

Save one versioned JSON/NPZ artifact per dataset/representation/training-partition, containing mu, measured sigma, effective sigma, pixel counts, min/max, natural zero fractions, guard settings, split IDs/hash, source commit/file hash, frontend config, input range, accumulation method/dtype, and artifact SHA-256. Use atomic writes and a file lock so concurrent GPU jobs share a single verified result. Save/restore the normalization values as fixed model buffers and include their hash in checkpoints and the run ID.

Freeze these 0%-sparsity statistics across ALL [0,20,40,60,80] settings, both architectures, all three training seeds, dense controls, validation, clean test, and corrupted test evaluation. Do not re-estimate after thresholding or for a different corruption/severity. A source/frontend/split change invalidates the statistics cache. At 0%, check that the full dense standardized training representation has approximately zero mean and unit population variance on non-guarded channels. This check is BEFORE token dropping. Do not expect retained-token distributions or sparsified/corrupted inputs to retain those same moments.

### 3.3 Coefficient sparsification and support

Use floating-point images in the range expected by the verified frontend. For the usual [0,1] input contract, convert uint8 to float32 by dividing by 255. Compute the frontend, coefficient ranking, support mask, and input standardization in float32 outside mixed-precision autocast. Do not apply raw RGB/grayscale mean/std normalization BEFORE the contrast frontend.

Define the requested percentage as a target fraction of ALL native representation coefficients per image, before adding implementation padding or any post-transform channel copies for a model interface:

    M = number of native representation coefficients
    n_remove = floor(sparsity_percent * M / 100)

Stable-sort coefficients by absolute NATIVE, UNNORMALIZED contrast magnitude, with native channel/raster order breaking ties. Set the first n_remove entries to exactly zero, preserving all other values and signs. At 0%, bypass percentile thresholding and sorting. Do not compute thresholds across a minibatch, dataset, class, or corruption category. An optimized implementation is allowed only after matching this deterministic reference. Per-channel standard deviations must NOT change the ranking rule by moving thresholding after normalization.

Existing zeros count toward the target. Actual zero fraction may exceed the requested percentage, and adjacent requested settings can produce the same tensor on already-sparse inputs. Report this; do not replace the definition with "remove p% of currently nonzero values." Count every native output channel, including identically zero opponent channels. Exclude only artificial spatial padding and any extra channel copies added AFTER the frontend solely for a model interface; do not silently change the denominator for MNIST.

For each non-overlapping patch j of the sparsified, UNNORMALIZED representation Cs:

    activity_j = max(abs(all native Cs coefficients in patch j))
    keep_j = activity_j > token_epsilon

Use token_epsilon=0.0 for the primary study. A fixed numerical-tolerance option is permitted only for explicitly labelled follow-up diagnostics, not a primary epsilon sweep or a way to force a token budget. Preserve original raster coordinates. Save the Boolean support independently of the numerical values fed into the embedding.

### 3.4 Standardize retained contrast without undoing token removal

Ordinary per-channel normalization is:

    Z[c] = (Cs[c] - mu[c]) / sigma_effective[c]

A thresholded zero would therefore become -mu[c]/sigma_effective[c] when mu[c] is nonzero. This does NOT provide new image information and MUST NOT cause an empty patch to be retained. Decide patch support on Cs BEFORE this affine transform, patch-projection bias, LayerNorm, or positional embeddings. Then gather retained patches and apply the affine transform to all their native coefficients before projection. Normalizing densely and then gathering by the ORIGINAL mask is an equivalent reference, but never recompute support from Z.

Inside a retained patch, apply the usual affine normalization even to coefficients that were zeroed; their resulting values may be -mu/sigma. Do not silently re-zero those coefficients after normalization, since that would be a different, masked-normalization method. Do not revert to RMS-only/division-only normalization, and do not center first then sparsify. Distinguish the fraction of zeros in native Cs from the numerical zero fraction after standardization and from physically absent tokens. The experiment's sparsity percentage refers to native Cs.

Entirely empty patches remain absent throughout compact execution. Any implementation-only sequence padding is inserted as masked, zero feature padding and never treated as image data. Structural padding and absent children in Swin feature-space merging are not standardized raw pixels. Use the identical native support and the identical affine transform in sparse and dense-masked reference paths. Dense 0%-contrast controls apply ordinary affine normalization without removing image patches.

Test explicitly with NONZERO channel means, partially zero patches, fully empty patches, and near-zero-variance channels. Verify that gathering then normalizing agrees with normalizing then gathering using the saved native mask, and that empty inputs still take the defined empty-image path. Never clip signed contrast or standardized values to [0,1] for training; display-only mappings must not enter the model.

Apply training augmentations to the raw image BEFORE contrast extraction and sparsification. Evaluation receives each official clean or corrupted image and applies the same frozen pipeline; never compute its support from a clean counterpart.

Use native representation channel counts in the patch stem and report parameter counts. MNIST is grayscale: its raw baseline is native grayscale, not RGB. For source modes requiring RGB, deterministically replicate the MNIST gray channel at the frontend input only. Do not fabricate color. Report duplicated contrast channels and zero/near-zero opponent channels, including their normalization guards. These MNIST encodings can be degenerate and must not be presented as independent evidence about color robustness. Retain all three requested configurations in the registry.

## 7. Genuine compact execution, including Swin

ViT:
Gather retained native contrast patches using pre-normalization support, standardize them with the frozen representation-specific per-channel mean/std, project them, and gather their ORIGINAL positional embeddings. Never renumber spatial positions after compaction. Always preserve the class token. Run attention and MLPs on shortened sequences. Handle a completely empty image with a class-token-only sequence, not an arbitrary retained image patch.

For batches with different retained lengths, begin with correct compact tensors padded only to the current batch's maximum retained length, with a valid padding mask. Instrument both useful tokens and actually executed padded lengths. Do not claim fully ragged computation when using padded batches. Packed variable-length execution or exact-length grouping is a permitted optimization after forward/backward parity tests. Packed sequences must never attend across images. Do not change minibatch membership or sample weighting merely to get convenient lengths.

Swin:
Do not flatten selected tokens and pass them to an unchanged dense Swin, resize the retained set into a new rectangular grid, or replace window attention with global attention.

Keep original coordinates and grid extents at every stage. Form shifted/unshifted windows using those coordinates and the appropriate cyclic-shift boundary rules. Gather only active tokens in each window; skip empty windows and group nonempty windows by retained length where useful. Relative-position bias must use the original within-window coordinate offsets, not compact sequence indices. Preserve shifted-window attention restrictions so cyclic wrapping does not connect unrelated boundaries.

Compute QKV projections, attention, output projections, and MLPs over active tokens, accounting explicitly for any execution padding. A dense full-window attention mask alone is not sparse attention. Avoid per-token Python loops; batch work over active tokens and length groups.

At patch merging, a parent exists if ANY of its four original children is active. Gather each existing parent's four children in the reference order, inserting zero vectors for missing children, then apply the standard merge normalization and projection. Skip entirely absent parents. Padding required by an odd stage dimension is structural padding, not image evidence. Do not let biases or normalization resurrect absent locations. Do not introduce additional feature-based pruning after merging.

At the end, pool active spatial features only. An image with no active features gets a defined zero pooled vector and finite classifier output. Do not add a fake spatial token. Keep stochastic-depth masks associated with original images, not with packed token or window indices.

Build a dense-masked REFERENCE execution of the same sparse semantics for correctness tests and timing controls. It must exclude missing keys, suppress inactive states after residual blocks, reproduce merging support, and use the same pooling. Sparse and dense-masked logits should agree within declared dtype tolerances. Ordinary dense attention over affine-standardized sparse patches without the saved support restrictions is a DIFFERENT model and is not the parity reference.

Later Swin stages may become effectively dense through merging. Measure this honestly. If the compact implementation is slower, report that. Do not substitute a different architecture, fabricate speedups, or label dense masking as physical token removal. A blocked Swin implementation must be identified as blocked while the valid ViT work continues.

## 9. Training recipe and validation discipline

Default starting recipe for clean-validation pilots:
- batch size 8, effective batch size 8, no gradient accumulation;
- AdamW, learning rate 3e-4, betas (0.9,0.999), weight decay 0.05;
- exclude biases, normalization parameters, and positional embeddings from weight decay;
- cosine learning-rate decay to 1e-6; warmup 5 epochs on MNIST and 10 on CIFAR-10;
- 50 epochs on MNIST and 200 on CIFAR-10;
- gradient clipping at norm 1.0;
- cross-entropy without Mixup, CutMix, distillation, or label smoothing;
- dropout 0 and a fixed stochastic-depth schedule from 0 to 0.1.

Use CIFAR-10 random crop with four-pixel padding and random horizontal flip. Use no augmentation for the initial MNIST study. No AugMix, corruption augmentation, color jitter, or robustness-specific training that would confound the input-representation question.

Treat these as starting experimental choices, not a claim of a published optimal recipe. Before the full sweep, verify loss reduction, finite gradients, and convergence of raw-input pilots; run an augmentation-free tiny-subset overfit check. If a recipe is clearly failing, debug first and make a small, logged clean-validation-only correction. Freeze one recipe per dataset/architecture before main runs; never tune separately for favorable sparsity levels or revisit it after seeing corruption results.

Use the same backbone initialization for a matched dataset/architecture/seed wherever shapes permit. Keep data-order and augmentation randomness independent of model RNG consumption. Train every main condition from a fresh initialization, not from another condition's checkpoint. Do not shorten weak conditions selectively or silently raise batch size to occupy GPUs.

Mixed precision is allowed for learned layers, preferably BF16 where supported, but keep the frontend and support decision in float32. Choose and log a consistent precision policy for each comparison group. Do not systematically assign baselines and contrast models different precision or hardware classes; balance assignments and record all hardware provenance.
