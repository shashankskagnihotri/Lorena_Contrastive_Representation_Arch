# Official data and fixed partitions

`python prepare_data.py --data-root /ceph/sagnihot/datasets --download` resolves and verifies data once. Workers consume `datasets_manifest.json`; they do not search the shared dataset tree. Inventory is saved in `provenance/datasets_inventory.json`. Existing originals remain unchanged. Download attempts, their exact URLs, checksums, and failure states are saved under `provenance/datasets_download_*.json`. Safe extraction rejects absolute paths, traversal, symbolic/hard links, and special files. Atomic directory creation provides cross-node exclusion; an existing lock is never automatically stolen.

MNIST, CIFAR-10, and CIFAR-10-C were already present. MNIST-C was downloaded from the official [Zenodo record](https://zenodo.org/records/3239543) and its MD5 matched `4b34b33045869ee6d424616cd3a65da3`. The official clean-data archive checksums and CIFAR-10-C archive MD5 are also checked. Existing MNIST IDX arrays are compared to their verified gzip originals; all CIFAR-10 extracted batches and metadata match the [torchvision publisher checksums](https://docs.pytorch.org/vision/stable/_modules/torchvision/datasets/cifar.html). The manifest retains SHA-256 hashes of archives and primary corruption arrays, along with dtype, full shape, range, labels, severity blocks, and coverage. No corrupted training arrays are used.

`outputs/splits/{mnist,cifar10}_seed2026.json` saves exact official indices, class counts, hashes, and panel identities; NPZ stores the same partition arrays. The split generator uses NumPy PCG64 seed 2026 and visits classes in ascending order. It allocates precisely 5,000 validation images proportionally by the largest-remainder method, breaking equal fractional remainders by ascending class ID. Each class's candidates are permuted once, then the combined selected indices are sorted. This leaves 55,000 MNIST and 45,000 CIFAR-10 training examples. Train and validation are disjoint and together cover every official training image. SHA-256 identities use UTF-8 `dataset/official_split/00000` strings in visit order, each followed by one newline. Official tests remain all 10,000 images. An explicit `full_refit`/`full_train_refit` protocol exposes all official training images and has no validation partition.

`load_clean(name, split='train', protocol='heldout_val')` and `CorruptionDataset(name, corruption, severity)` return `(uint8_CHW_tensor, integer_label, stable_sample_id)`. Native shapes are `(1,28,28)` and `(3,32,32)`. Corruption arrays are memory mapped, transposed explicitly from HWC, and copied per sample so read-only source arrays cannot be accidentally modified. Dataset objects expose `sample_ids`, `split_hash`, `labels`, and `targets`; clean datasets also expose `indices`.

The primary CIFAR-10-C list contains exactly 15 corruptions, with all five severity blocks `[(s-1)*10000:s*10000]`, totaling 750,000 predictions per checkpoint. Its actual `labels.npy` shape is `(50000,)`; every severity block was checked against clean CIFAR-10 test labels. The four supplemental corruptions are excluded from the primary mean. Standard MNIST-C contains 15 primary corruptions, each at released severity `fixed`, totaling 150,000 predictions per checkpoint. Every primary label array matches the official MNIST test ordering. Identity is excluded. Registry constants and `corruption_cells(name)` encode these protocols directly.

Panels use an independent PCG64 seed (9421 for train, 9422 for validation, 9423 for test) and are class-interleaved. Diagnostic panels contain one saved image per class. Timing panels contain 160 images per class (1,600 images), selected without model output, support, or latency. The test panel's original identities define corresponding corruption panels and timing batches. Full accuracy never uses these subsets.

MNIST receives no augmentation. CIFAR-10 receives constant-zero padding of four pixels, a uniform 32x32 crop, and a probability-1/2 horizontal flip before the frontend. Augmentation decisions use a private PCG64 instance keyed by SHA-256 of namespace, training seed, epoch, and stable sample ID. Epoch order has an independent namespace. Model RNG, diagnostics, worker ordering, and resume cannot advance these streams. Call `set_epoch()` before each loader iterator and use nonpersistent workers (or zero workers); the epoch is copied into workers at iterator creation. Epoch-boundary replay recreates the same images and sample order.

Raw-input normalization uses the requested fixed [PyTorch MNIST example](https://github.com/pytorch/examples/blob/main/mnist/main.py) constants `(0.1307,)/(0.3081,)` and the chosen published [kuangliu CIFAR-10 recipe](https://github.com/kuangliu/pytorch-cifar/blob/master/main.py) constants `(0.4914,0.4822,0.4465)/(0.2023,0.1994,0.2010)` on `[0,1]` inputs. These are not estimated from this project's test data and never substitute for contrast-specific statistics.

The user-revised representation scope in `experiment_scope.json` keeps MNIST raw/grayscale and all three CIFAR-10 contrast representations. Split identities and sample counts are unchanged. Active contrast normalization consists of four fits, one MNIST and three CIFAR-10, with eight native channel rows. The full-training preprocessing table contains 60 active rows: 15 MNIST and 45 CIFAR-10 across five sparsities and patch sizes 1, 2, and 4. Withdrawn MNIST single-color/opponent artifacts are excluded and were removed at the user's request.

For this larger-batch rerun, raw dataset locations remain shared and read-only. The four split files and active normalization artifacts are byte-identical local copies from the prior campaign. `datasets_manifest.json` points to this campaign's local split files, and its new file hash enters every resolved configuration. Normalization is reusable because the frontend, population, split identities, and fitting procedure did not change with optimizer batch size.
